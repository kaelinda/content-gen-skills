# 公众号写作经验：跨 Agent 工作手册

本手册承接技术号、育儿号的长期编辑偏好，不依赖某个 Agent 的记忆或专有工具。
执行入口仍是本仓库 `publishing-wechat-articles/scripts/pipeline.py`，不是 `vendor/` 中的历史脚本。
本手册、主 Skill 与当前合同优先于历史快照；用户本次明确要求优先于默认写法，
但不能绕过真实证据、隐私与外部操作授权。

## 1. 先判断这篇文章值不值得写

写前用三句话交代：

- **给谁看**：具体读者、场景、当前问题。
- **看完能做什么**：一个判断、操作、避坑方法或可核查的行动清单。
- **比原文多什么**：比较、边界、决策框架、实操验证或有证据的作者经验。

只有“把推文翻译一下”时，不强行扩成长文。技术文章不要堆 API、README、
产品功能或会议纪要；育儿文章不要靠焦虑和夸张的后果吸引读者。
先查已有资料是否重复，并在 `research.json` 记录真实检查范围。

## 2. 服从阶段审核，不扩大「继续」的授权

建议按「选题清单 → 角度/提纲 → 正文 → 图文终审 → 待发布交接」推进。
用户要求先清单、审核后写作时，「继续」「继续推进」只允许继续当前清单修改，
不等于批准写正文，更不等于批准上传或发飞书。

写作完成不等于终审通过。明确说出当前阶段、证据和需要用户决定的事项。
默认使用 `prepare-only`；迁移配置、安装依赖或补齐密钥均不构成发布授权。

## 3. 资料分层：原文、官方事实、作者判断

- 原始资料保留来源 URL、作者、日期、正文和原图清单，不能只留二次摘要。
- X 帖子有外链时单独读取外链正文；线程和长文不完整时停止引用缺失段落。
- 重要版本、模型、价格、API、兼容性和数字去官方文档/仓库核实。
- 明确区分「来源作者声称」「官方资料确认」「我的判断」；无法核实就缩小表述。
- 美元价格需要给人民币参考时查询当次汇率，标注日期和估算；不把旧固定汇率当事实。
- 知识页记录可复用原则与适用边界，文章面向读者问题；两者都不只是原文改写。
- 浏览器不可用时可以用公开页面/API或用户提供材料，不得伪称已登录抓到全文。

原始资料、概念页、文章与交付记录分开保存。仅建立确实存在的知识页链接。

## 4. 技术号：像开发者给同事解释问题

**AICoder / 极客黑**。推荐因果链：遇到什么问题 → 为什么发生 → 可用选择 →
我的取舍 → 如何验证 → 哪些情况不适用。

- 先给直觉解释，再给必要原理；代码只保留真正帮助读者执行和判断的部分。
- 可以用第一人称表达判断，不可编造“我上线后”“我们团队实测”等经历。
- 用户要口语化时使用短句、自然转折和具体对象，不为装真人虚构故事。
- 官方账号/权威机构为主来源时，标题突出「来源 + 动作 + 具体收益」；
  不虚构“提升十倍”、排名、用户量或其他量化承诺。
- 个人开发者项目可用数字和痛点组织标题，但数字必须是文章真实覆盖的内容。
- 实测代码应记录版本、命令和结果；未运行的标为示例/未实测。
- 成本、认证、权限、安全、地区和预览功能的边界不能省略。

## 5. 育儿号：温暖、具体、有证据

**育儿育己 / 橙心**。围绕具体年龄、场景、家长能说的话和可执行动作展开。

- 不制造恐惧、不给孩子贴诊断标签，不把复杂问题归咎于父母。
- 研究结论标明来源与适用范围；涉及医疗/发育问题需重新核实专业来源和就医边界。
- 第一人称经历、孩子的原话、读者投稿必须确认真实并保护隐私。
  未核实的案例标为「假设场景」或「待作者确认」，不能冒充自己的经历。
- 可按“识别—区分—行动”组织系列，也可拆成“理论—话术”姊妹篇；
  这是结构选择，不是已验证阅读量或完读率的保证。
- 系列中相互引用的方法名称、数量和适用年龄必须一致。
- 不拿“定稿”文件名、封面完成或自动检查通过作为可发表证据。

## 6. 长度与去模板化

按读者需要决定长度。默认长文目标见 `writing-contract.md`；用户要求精简时取消
最低字数，通常可控制在约 1500–2000 字，但内容更短也可，只要交付完整。
用户说「不限字数」时不强行压到 3000–4000 字。不要为达标扩写空话。

重点扫描：机械的“首先/其次/最后”、反复“不是……而是……”、
“值得注意的是”“总的来说”“在当今……”和重复总结。
逐段修正后对**整份最终文件**再检查一次，包括标题、摘要、图注和结尾。
专业语境中的合法用法按上下文判断，不盲目批量替换，不改坏代码和引用。

扩写只增加有证据的对比、机制、适用边界或验证过程；不凭空补个人经历。
正文不重复总标题；使用 `##` / `###` 真正的小标题，不用粗体假装标题。

## 7. 封面和正文图片是两件事

- 技术新闻优先考虑相关的原图；用户要求“封面自己生成”时必须新建封面，
  原图只能作为相关的正文素材，不得拿来冒充生成结果。
- 官方宣传图、OG 卡片不能冒充功能截图或架构图。图必须解释附近的具体内容，
  说明读者应看哪里；没有合适图片宁可标记缺口。
- 先下载和检查原图，保留来源；准备阶段使用本地资源，授权发布时上传 OSS，
  重写最终 HTML 引用，不直接热链不稳定的第三方图片。
- 新封面通常交付 1200×540，检查真实像素、裁切、中文文字和移动端效果。
  不能只凭 HTTP 200、文件后缀或脚本退出码认定图片合格。
- 已审核的封面可复用；标题变更后重新确认封面，不无故重生成。
- 图片服务与模型可用性会变化。请求的模型、载体模型和响应报告的模型分别记录，
  不把配置项、列表可见或历史成功当作本次实际生成证据。
- Codex 订阅登录和普通 API Key 是不同认证方式。不要把订阅 token 塞进 `.env`，
  不自动复制浏览器 Cookie 或登录文件，也不把代理 Key 发到未经确认的端点。
- 本仓库现有 Images API 适配器与 HTML 模板保持独立；迁移并未自动提供订阅生图
  适配器。需要订阅路径时在目标 Agent 显式配置其能力，核实模型后再授权调用。
  模板封面不能描述为 AI 生图；失败不能静默改模型或反复扣费重试。

## 8. 交付与发布状态

1. 技术使用极客黑，育儿使用橙心；先审核正文和图片，再生成可粘贴的 HTML。
2. 技术号、育儿号可以交接到同一配置会话，但表格目标按频道分开。
3. 每篇独立发送**一条**标题、摘要、封面 URL、HTML URL 的消息。
   不把正文拆段发给飞书，不把多篇文章打包成一条交接消息。
4. 飞书写表前读取当前字段名和类型；`是否已发布` 写布尔值 `false`。
5. 上传读取公网字节/MIME；发消息读取精确 message ID；写表读取精确 record ID。
   模糊超时先核对远端，不能直接重发制造重复。
6. OSS 上传、飞书交接、表格记录、公众号草稿和公开发布分别报告。
   交接成功不能说“公众号已发布”。

AI 辅助 + 作者编辑和原创增量是质量要求，不是平台合规保证。发表时重新核实平台
的标识、版权、科学准确性和隐私要求，按实际情况声明。

## 9. 新 Agent 的最短交接提示词

> 先读取本仓库 `AGENTS.md`、`publishing-wechat-articles/SKILL.md` 和
> `publishing-wechat-articles/references/editorial-playbook.md`。复用仓库统一 CLI，不执行 vendor 历史脚本。
> 凭证从根目录 .env 读取，不打印值。先确认读者价值和审核阶段，默认只准备不发布；
> 缺失资料或登录状态如实报告，最终分别报告文章、图片、交接和发布的实际状态。
